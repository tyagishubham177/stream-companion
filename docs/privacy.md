# Privacy

Stream Companion sends lookup title names, corresponding release years, media types or IMDb IDs to `https://www.omdbapi.com/`. The OMDb key accompanies provider requests. OMDb also receives normal connection metadata such as IP address.

For automatic identity matching, the public Netflix and JioHotstar IDs of visible titles are sent in separate, small batches to `https://query.wikidata.org/sparql`. Wikidata returns community-maintained streaming-to-IMDb identifier links and receives normal connection metadata. It never receives the OMDb key, streaming credentials, cookies, account/profile identifiers or playback history. Saved mappings and fresh caches avoid repeating these queries on every visit.

When a direct ID relationship is missing for a film, the worker requests its public Netflix title page from `https://www.netflix.com/in/title/:id`. This fixed public India/English catalogue route does not read or change the Netflix account’s region. Requests omit cookies, authentication and referrers, and never include the OMDb key. Netflix receives the public title ID and normal connection metadata. Only the film name, movie type, visibly displayed release year and public director/cast credits are extracted; scripts and private application state are not executed or read. Accepted metadata is cached locally for 30 days, genuine unsupported/missing pages for one day. It is not collected for off-screen browsing history.

Preferences, saved mappings, provider key, request accounting and metadata cache stay in this browser profile. The key is restricted to trusted extension contexts and never returned to page scripts or diagnostics. The extension does not use streaming account/profile IDs, cookies, private endpoints, viewing-history events or analytics.

Local title mappings and caches contain title metadata and matching provenance. Diagnostics use aggregate counts and settings only, excluding title records, raw URLs, credential fingerprints and keys. Opening IMDb, OMDb or Wikidata links deliberately visits those sites under their own privacy practices.

Clear ratings cache, reset saved matches and remove key are independent actions. Request usage/cooldowns remain after these operations to preserve conservative accounting. Uninstalling the extension removes extension-managed browser data; its local estimate cannot account for a key used elsewhere or data lost by uninstall/profile reset.

Edition and language-label matching compares public Netflix director/cast credits with optional OMDb work credits, together with the complete film title and release year. These are public film credits, not account data. They remain in the same local metadata/score caches; no new third-party service or user credential is introduced.

## Local matching log (0.4.0)

At the user’s request, the extension records matching evidence locally: public title IDs/names and observed year/type, automatic source outcomes, enriched movie metadata, actual OMDb search filters, candidates in returned order and failed checks. Manual correction sessions record searches, selected previews and confirmed matches. Only a successful confirmation is a correction label; previewing alone is not. Confirmations preserve the relevant automatic decision and the chosen search’s page, position and rank. Direct IMDb entry has no inferred search rank; the entered URL is not retained. Removing or resetting saved identities is recorded as a subsequent withdrawal, not silently treated as a permanent correct label.

This is title/search history and may reveal browsing interests. It remains in the extension database, with no telemetry, automatic upload or model training. Up to 1,000 matching records are retained for 30 days, including at most 500 automatic decisions. Repeated cached outcomes reuse the original evidence instead of adding a record on every scroll. Old records are pruned at worker startup, new writes, periodic maintenance and export. A confirmed event embeds its automatic evidence and selected search metadata, so its essential context survives eviction of individual search/preview events.

Settings → Data & privacy → Review matching log displays the JSON locally and reports how many search selections confirmed the first result. Download matching log saves only that reviewed snapshot. Sharing the downloaded file is a separate user action. The ordinary Download diagnostics export continues to exclude title/search history. Neither export includes the stored OMDb credential, credential fingerprints, raw provider responses, request URLs/headers, account identifiers, cookies or playback events.

Clear matching log deletes these records and cached diagnostic traces, increments a durable logging generation to reject in-flight old writes, and expires open correction sessions. Saved matches, rating/source caches, key, request accounting and cooldowns remain. New matching activity can create new records; it cannot restore an old cleared search trace. Clearing or uninstalling cannot remove copies the user already downloaded.

The feature starts recording after this version is reloaded. Earlier correction searches cannot be reconstructed. Previously cached failures may have only a cached-stop reason until a new matching attempt supplies detailed evidence. Logs are diagnostic observations and user confirmations, not an independently validated training dataset.

## Your marks and feature controls (0.5.0)

Explicit watched/plan choices, display-title snapshots, modification times, revisions and short-lived Undo inverses remain in this Chrome profile. They are keyed by platform and title, and shared across streaming profiles used in that Chrome profile. The extension does not change the platforms’ watchlists or reactions or monitor playback. Marks require neither an OMDb key nor a resolved IMDb identity, have no cache expiry, and are separately exportable/resettable from Your titles. Export includes active marks; reset deletes the marks store and advances its generation so stale edits/Undo cannot restore it. Ordinary clear actions retain revision tombstones for stale-write protection.

Module toggles pause their feature and preserve saved data. Disabling matching-log recording also stops new diagnostic traces in resolution caches; existing records remain until cleared. Automatic matching can be paused while saved identities and cached ratings remain usable. Ratings and artwork treatments can be switched off independently.

Series matching reads only bound public TVSeries metadata and cast, never treats the visible season year as a series start year. Optional title-query lookups send the same public film name/year/type to OMDb as existing searches; a different returned name requires corroborating director/cast and year/type proof. No new provider origin or ordinary browser permission is introduced. Classic New & Popular cards use only scoped public video_id/unifiedEntityId fields to corroborate a title; raw tracking context and its other fields are not stored or transmitted.

## JioHotstar support (0.6.0)

JioHotstar observations use whole-title IDs from supported links and public metadata in the current page. A Continue Watching episode link can identify its parent show; the episode ID and progress are ignored. Only canonical detail paths are saved, without query strings or tracking parameters. Public cast is read only on the matching detail page and compared locally. The extension does not fetch JioHotstar title pages in the background, read account state, or send cast names, platform URLs, marks, or streaming credentials to OMDb. Its only added site access is `www.hotstar.com`, with content scripts scoped to the India site.

The extension keeps up to 512 verified poster associations locally in this Chrome profile. An association stores a public artwork identifier, normalized title and media type, canonical title path and ID, and any confirmed displayed year or season count. It is learned only when Hotstar shows an unambiguous preview for that exact poster. Associations survive page reloads, contain no event timestamps or account identifiers, and are removed when the extension is uninstalled. They are not exported in diagnostics or sent to any provider; ordinary lookups still use the verified public title as described above. A small list of public poster associations ships with the extension. IMDb scores already displayed by Hotstar are rendered directly from the page.
